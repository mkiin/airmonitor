SCD41 · OBJECT DIAGRAM

測定処理の時間管理を、どこが持つか

各箱は実行時のオブジェクト、矢印は呼び出しやイベントです。単発測定 API は削除済みですが、周期測定の経路には vendor 関数内の待機が残っています。

01

現状：待機が呼び出しの内側にある

測定タスクから見ると、センサーコマンドの途中でいつ待つかが隠れています。

問題の境界HAL の sleep_usec が OS API を直接呼ぶ。
まだ残る待機停止後 500ms、準備確認と値取得で各 1ms。
単発測定5秒待機を含む単発 API は削除済み。図には含めない。
02

対策案：状態とタイマーイベントを測定タスクが持つ

コマンド送信、センサー内部の処理待ち、応答読取を別の遷移に分けます。これは設計案で、現行コードには未実装です。

状態遷移停止送信 → 500ms → 開始 → 5秒 → 準備確認送信 → 1ms → 状態読取 → 測定値要求 → 1ms → 値読取。
イベントの受け手タイマーは通知だけ。I²C 操作は測定タスクが行う。
ドライバーの範囲使うコマンドだけを持つ小さなプロトコルドライバーへ置換する。

変更する境界

時間の所有者を vendor API / HAL から measure : StateMachine に移す。I²C 自体は短い同期トランザクションのままでよく、センサー処理の待ち時間だけをイベントに分ける。

現状はリポジトリのコードに基づく。対策案は設計図であり、実装済みの動作を示すものではない。
